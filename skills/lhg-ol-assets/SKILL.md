# lhg-ol-assets：launch 素材

> **诚实声明**：本 skill 不编造任何数据；素材中不出现无依据的数字；"一键成片指引"只出文案与分镜，不做视频渲染。

## 1. 何时使用

- README 已就绪（见 lhg-ol-readme），发布日临近，需要准备各平台发布素材时。
- 用户说"帮我写个 Show HN 帖子""推文怎么写"时，直接用第 3 节对应平台的写法。
- `/lhg-oss-launch:oss-assets` 命令全程按本 skill 执行，输出到 `launch/` 目录。

**模式来源**：本 skill"一句话输入、多形态输出"的思路借鉴自 latent-spaces/brag（一句话生成 launch video 的模式），实现与文案均为原创（见 ATTRIBUTION.md）。

## 2. 输入输出

### 输入
- `launch-brief.json`（one_liner、audience、pain、differentiator、evidence、gaps）

### 输出（`launch/` 目录）
| 文件 | 内容 |
|---|---|
| `x-thread.md` | X 推文串：首推钩子 + 3~5 推展开 + 收尾 CTA |
| `hn-post.md` | Show HN 帖子：标题 + 正文 |
| `ph-launch.md` | Product Hunt：tagline + 描述 + 首评话术 |
| `demo-script.md` | 演示文案 + 90 秒分镜 |
| `shoot-guide.md` | 一键成片指引：封面/字幕/配文模板 |

每份文件顶部标注建议发布时间。

## 3. 分步方法论：四平台写法

### X 推文串（x-thread.md）
1. **首推钩子**：一句话痛点或反常识结论，≤140 字，结尾留悬念。不许"很激动地宣布……"开头。
2. **展开 3~5 推**：每推一个卖点，配证据（截图/GIF 链接）；卖点按"最痛的先说"排序。
3. **收尾 CTA**：一句话 + 仓库链接 + 求转发话术（"觉得有用请转发"只许出现一次）。
4. 中文语境可直接用中文推文；配 1~2 个话题标签。

### Show HN 帖子（hn-post.md）
1. **标题**：`Show HN: 项目名 – 一句话介绍`，一句话介绍 ≤80 字符。
2. **正文结构**：做了什么（2 句）→ 为什么做（痛点故事）→ 技术点（HN 读者爱看实现细节）→ 求反馈（具体问题，如"Windows 兼容性求测试"）。
3. **语气**：工程师对工程师，不吹牛；技术取舍诚实写（"为了简单，暂时不支持 X"）。
4. **评论区准备**：预写 3 个可能被问到的问题的回答（性能/竞品/roadmap）。

### Product Hunt 描述（ph-launch.md）
1. **tagline**：60 字符内，用户视角："一句话整理下载文件夹"。
2. **描述**：3~4 句，第一句讲价值，后面讲 2 个核心功能 + 适用人群。
3. **首评话术**：以 maker 口吻写首条评论（为什么做、求什么样的反馈），发布时自己先发。
4. **配图建议**：首图用 GIF（产品动起来），标注尺寸建议。

### 演示文案 + 分镜（demo-script.md）
1. **90 秒三段式**：痛点 15s（展示混乱现场）→ 演示 60s（一句话操作 + 结果，3 个镜头）→ 收尾 15s（一句话价值 + 仓库地址）。
2. **口播文案**：按分镜写逐字稿，每 15 秒一段，口语化。
3. **镜头表**：每个镜头写"画面/操作/时长/字幕"，可直接交给剪辑。

## 4. 一键成片指引（shoot-guide.md）

- **封面帧**：取演示中最"整洁"的一帧（操作完成后的结果画面），文字 ≤10 字。
- **字幕**：关键操作配字幕，字号适配手机竖屏。
- **配乐**：注明"用无版权音乐"，不指定具体曲目。
- **配文模板**：标题 + 一句话介绍 + 仓库链接 + 话题标签，可直接复制发布。
- **说明**：本插件只出指引与文案；实际渲染可用 brag 等视频工具另行完成。

## 5. 差异化检查

- 四份素材首段不许完全相同：同一卖点在 X 上讲痛点、在 HN 上讲技术、在 PH 上讲体验。
- 检查方法：并排读四份首段，连续 3 句相同即判不合格，重写。
- 发布时间建议：X（北京时间工作日晚 8~10 点）、HN（北京时间周二~周四上午，对应美西周一晚~周三）、PH（北京时间周二 0 点，抢首日流量）。

## 6. 反模式

1. **一稿四发**：同一文案复制粘贴发四个平台——每个平台的读者和调性都不一样。
2. **数字撑场面**："已有 10000+ 用户"——发布第一天写这个，评论区第一个问题就是"数据哪来的"。
3. **钩子党**：首推只放悬念不放信息（"明天有个大消息"）——开源发布要的是信息密度，不是营销号。
4. **技术黑话堆砌**：PH 描述写"基于事件驱动架构"——PH 读者要的是"它能帮我干什么"。
5. **无 CTA**：通篇介绍，结尾没有"去试试/给个 star/提 issue"——转化全靠 CTA 那一句。

## 7. 素材复用与二次传播

发布日之后，素材不要一次性烧完。按以下节奏复用：

### 发布后 24 小时
- 整理评论区高频问题，更新 README 的 FAQ（或新增）。
- 把 HN/X 上讲得好的用户评论截图（经对方同意），存为后续素材。

### 发布后 1 周
- 发"发布一周复盘"帖：真实数据（star 数、issue 数、PR 数——此时都是真实的）、用户反馈、下一步。
- 复盘帖的数据全部真实，这是 OL-TRUTH 规则不再拦截你的第一天。

### 发布后 1 个月
- 把 launch 素材改写成教程/博客："我是怎么做这个开源项目的"。
- 教程的受众是"想做开源的人"，不是"想用工具的人"——换受众、换钩子。

### 素材库维护
- `launch/` 目录保留每次发布的素材，文件名带日期（`x-thread-2026-10-11.md`）。
- 下次发新版本时，对比上一版素材，复用结构、换内容，不许直接重发。

### 发布日时间线（示例）
- T-7 天：README 定稿，审计 blocker 清零。
- T-3 天：四份素材写完，找 2 个朋友试读（X 串找非技术朋友，HN 帖找技术朋友）。
- T-1 天：演示视频成片，封面帧确认；PH 素材上传草稿。
- T 日 0 点（北京时间）：PH 发布；上午：HN 帖子；晚 8 点：X 推文串。
- T+1 天：回复所有评论；整理高频问题进 README。

### 失败预案
- 帖子沉了（2 小时无回复）：不删帖，在评论区自己补一条"补充个技术细节"，顶一下。
- 被质疑数据：拿出 benchmark 方法或承认不足，不许删帖跑路。
- 被指出 bug：当天修，发 hotfix，并在评论区更新——这是最好的二次传播。
- 被误解定位（"这不就是 XX 吗"）：用 differentiator 一句话回应，不争吵、不删评。

### 素材自查四问（发布前夜）
1. 每份素材的首句，路人能看懂吗？
2. 所有链接点一遍，都有效吗？
3. 所有数字都有来源吗？
4. 如果只能留一份素材，你留哪份？为什么？（答不上来说明钩子不准，重写）
5. 发布时间标注了吗？时区写的是北京时间吗？
6. 成片指引里的封面帧，手机上能看清吗？（自己用手机打开看一遍）

## 8. 自检与反馈

### 质检门（素材输出自查）
- [ ] 四份素材首段是否差异化（连续 3 句相同即不合格）？
- [ ] 是否无编造数字、无绝对化宣称（或已给限定条件）？
- [ ] 每份素材是否有发布时间标注？
- [ ] demo-script.md 分镜是否 90 秒三段式、口播稿是否逐字？
- [ ] gaps 中的缺项是否未出现在素材中？

### 标准冒烟用例
输入：launch-brief.json（evidence 有 1 张 GIF，gaps 含"缺性能数据"）。
期望输出：4 份素材 + 成片指引；X 首推为痛点钩子；HN 正文有技术取舍说明；PH tagline ≤60 字符；demo-script 为 90 秒三段式；无性能数字出现。

### 一键反馈
发现素材问题，以 `[QC] lhg-ol-assets <一句话>` 为标题提交到 https://github.com/lhg-plugs/lhg-oss-launch/issues，正文写清"输入 brief → 实际素材 → 期望素材"。
